# กลุ่ม G · ความน่าเชื่อถือ / ปลอดภัย

> กลุ่มนี้ไม่ใช่ "ของเสริม" — เว็บที่เก็บชื่อและเบอร์ลูกค้าควรมี G1 กับ G2 ตั้งแต่วันแรก

---

## G1 · คีย์อยู่ใน env เท่านั้น + เช็กลิสต์ก่อน push  **[ห้อง]**
**ต้องมีก่อน:** ฐาน
**แตะไฟล์:** ทั้งโปรเจกต์ (ตรวจ ไม่ได้แก้เยอะ)

```
อ่าน CLAUDE.md เป็นบริบทก่อน แล้วตรวจความปลอดภัยให้ทั้งโปรเจกต์:
1. ไล่หารหัสผ่าน คีย์ เบอร์บัญชี หรือ connection string ที่ hardcode อยู่ในไฟล์ไหนบ้าง
   ถ้าเจอ ย้ายไปเป็น environment variable แล้วเพิ่มชื่อลงใน .env.example
2. เช็กว่า .gitignore กัน .env, node_modules และ data/ แล้ว
3. เช็กว่าไฟล์ฝั่งหน้าเว็บ (public/*) ไม่มีรหัสผ่านหรือคีย์อะไรอยู่เลย
4. เช็กว่าทุก route ที่ขึ้นต้นด้วย /api/admin ผ่านการตรวจรหัสผ่านจริง ๆ
รายงานเป็นตาราง: พบอะไร / ที่ไฟล์ไหน / แก้ยังไง
```
**ทดสอบ:** ค้นทั้งโปรเจกต์ด้วยคำว่า password และ key → ไม่เจอค่าจริงในไฟล์ที่จะ push
**ถอดมาจาก:** กติกาข้อ 1 ของ Bookly

## G2 · ขอความยินยอมเก็บข้อมูลส่วนบุคคล (PDPA)  **[ห้อง]**
**ต้องมีก่อน:** ฐาน (จำเป็นทันทีที่มี A1 หรือ B1)
**แตะไฟล์:** `public/privacy.html` `db.js` + ทุกหน้าที่มีฟอร์ม

> ฐานมีหน้า `/privacy` เป็นแบบร่างไว้ให้แล้ว บล็อกนี้คือ "ทำให้ใช้ได้จริง"

```
อ่าน CLAUDE.md เป็นบริบทก่อน
เว็บนี้เก็บชื่อ เบอร์โทร และอีเมลของลูกค้า ช่วยทำให้ถูกต้องตามหลักการคุ้มครองข้อมูลส่วนบุคคล:
1. ทุกฟอร์มที่เก็บข้อมูลส่วนตัว ต้องมีช่องติ๊กยินยอมที่ผู้ใช้ต้องกดเอง
   (ห้ามติ๊กไว้ให้ล่วงหน้า) พร้อมลิงก์ไปหน้า /privacy
2. บันทึกลงในข้อมูลด้วยว่า ยินยอมเมื่อไร และยินยอมกับนโยบายเวอร์ชันไหน
3. เขียนข้อความสั้น ๆ ข้างช่องติ๊ก บอกตรง ๆ ว่าเก็บอะไร เอาไปทำอะไร เก็บนานแค่ไหน
4. หน้า /privacy เติมช่องว่างในวงเล็บเหลี่ยมให้ครบตามข้อมูลร้านฉัน: <บอกข้อมูลร้าน>
5. เพิ่มช่องทางให้ลูกค้าขอลบข้อมูลของตัวเอง (แค่บอกวิธีติดต่อก็พอ)
หมายเหตุ: นี่ไม่ใช่คำแนะนำทางกฎหมาย — ถ้าเก็บข้อมูลอ่อนไหวหรือข้อมูลเด็ก ควรปรึกษาผู้รู้ก่อน
```
**ทดสอบ:** ไม่ติ๊กยินยอม → ส่งฟอร์มไม่ได้ และขึ้นข้อความบอกเหตุผล
**ถอดมาจาก:** ใหม่ — ไม่มีในเว็บไหนของเราเลย ซึ่งเป็นช่องโหว่ที่ควรปิด

## G3 · กันสแปม/บอทในฟอร์ม + จำกัดการยิงซ้ำ  **[บ้าน]**
**ต้องมีก่อน:** A1 หรือ B1
**แตะไฟล์:** `server.js` + หน้าที่มีฟอร์ม

```
อ่าน CLAUDE.md เป็นบริบทก่อน
กันคนกดส่งรัว ๆ และกันบอทยิงฟอร์ม:
1. ฝั่งเซิร์ฟเวอร์ — จำกัดจำนวนครั้งต่อ IP เช่น ไม่เกิน 5 ครั้งต่อ 10 นาที
   เกินแล้วตอบข้อความสุภาพ ไม่ใช่ error ดิบ ๆ
2. ฝั่งหน้าเว็บ — กดปุ่มส่งแล้วปิดปุ่มทันทีจนกว่าจะได้คำตอบ
3. เพิ่มช่องซ่อน (honeypot) ที่คนมองไม่เห็น ถ้ามีค่ากรอกเข้ามาให้ทิ้งเงียบ ๆ
4. ตรวจรูปแบบเบอร์โทรและอีเมลทั้งฝั่งหน้าเว็บและฝั่งเซิร์ฟเวอร์
อย่าใช้ captcha — ลูกค้าสูงอายุจะทำไม่ได้
```
**ทดสอบ:** กดส่งรัว 10 ครั้ง → มีแค่ใบเดียวเข้าระบบ
**ถอดมาจาก:** ใหม่

## G4 · หน้าหลังบ้านไม่มีทางเข้าจากหน้า public + ล็อกทุกครั้ง  **[ห้อง]**
**ต้องมีก่อน:** ฐาน
**แตะไฟล์:** `server.js` `public/admin.html`

```
อ่าน CLAUDE.md เป็นบริบทก่อน
เข้มงวดเรื่องทางเข้าหลังบ้าน:
1. ตรวจว่าไม่มีลิงก์ไป /admin จากหน้า public เลยแม้แต่จุดเดียว
2. ใส่ meta robots noindex ในหน้า admin เพื่อไม่ให้ขึ้น Google
3. ปิดหน้าแล้วเปิดใหม่ต้องใส่รหัสใหม่ทุกครั้ง ห้ามจำรหัสไว้ในเบราว์เซอร์
4. ใส่รหัสผิดเกิน 5 ครั้ง ให้รอ 1 นาทีก่อนลองใหม่
5. ตรวจว่า /api/admin/* ทุกเส้นผ่าน requireAdmin จริง — ลองเรียกตรง ๆ โดยไม่ใส่รหัสแล้วต้องถูกปฏิเสธ
```
**ทดสอบ:** เปิด `/api/admin/items` ในเบราว์เซอร์ตรง ๆ → ต้องได้ 401 ไม่ใช่ข้อมูล
**ถอดมาจาก:** กติกาข้อ 5 ของ Bookly + โหมด kiosk ของ Seed POS
