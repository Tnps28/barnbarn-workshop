# prompts.md — พรอมต์ก๊อปวาง เรียงตามลำดับที่ใช้จริงในวันเรียน

**วิธีใช้:** เปิดโฟลเดอร์นี้ใน Claude (Cowork หรือ Claude Code) แล้วก๊อปพรอมต์ไปวางทีละอัน
ทำตามลำดับ อย่าข้าม — พรอมต์แต่ละอันต่อยอดจากอันก่อนหน้า

> **เคล็ดลับประหยัดโควตา**
> · สั่งทีละงาน อย่าสั่งพรวดเดียวหลายอย่าง
> · บอกให้แก้เฉพาะไฟล์ที่เกี่ยว อย่าให้อ่านทั้งโปรเจกต์
> · ขึ้นต้นด้วย "อ่าน CLAUDE.md เป็นบริบทก่อน แล้ว…" ทุกครั้ง

---

## 0) ให้ AI รู้จักโปรเจกต์ก่อน
```
อ่านไฟล์ CLAUDE.md เพื่อเข้าใจโปรเจกต์นี้ แล้วสรุปสั้น ๆ ว่ามันทำอะไรได้บ้าง
และไฟล์ไหนทำหน้าที่อะไร อย่าเพิ่งแก้อะไร รอคำสั่งถัดไป
```

## 1) เล่าให้ฟังว่าร้านเราทำอะไร
```
อ่าน CLAUDE.md เป็นบริบทก่อน
ร้านของฉันชื่อ <ชื่อร้าน> ขาย <อธิบายสินค้า/บริการ>
ลูกค้าหลักคือ <ใคร> สิ่งที่อยากให้ลูกค้าทำบนเว็บคือ <จอง/สั่งซื้อ/ดูข้อมูลแล้วทักแชท>
โทนที่อยากได้คือ <อบอุ่น / เรียบง่าย / พรีเมียม>
ยังไม่ต้องแก้โค้ด — ช่วยบอกก่อนว่าจากฐานนี้ ต้องแก้อะไรบ้างถึงจะตรงกับร้านฉัน เรียงลำดับให้ด้วย
```

## 2) รีแบรนด์ — ชื่อ โลโก้ สี
```
อ่าน CLAUDE.md เป็นบริบทก่อน
เปลี่ยนค่าตั้งต้นในฟังก์ชัน seed() ของ db.js ให้เป็นของร้านฉัน:
ชื่อร้าน "<ชื่อ>" · โลโก้อีโมจิ <emoji> · คำโปรย "<คำโปรย>"
หัวข้อหน้าแรก "<หัวข้อ>" · ข้อความใต้หัวข้อ "<ข้อความ>"
และเปลี่ยนสีหลักเป็นโทน <บอกสี> สีรองเป็นโทน <บอกสี> ทั้งใน seed() และตัวแปรใน public/css/styles.css
แก้เฉพาะสองไฟล์นี้ อย่าแตะ route หรือชื่อ field
```

## 3) ใส่รายการจริงของร้าน
```
อ่าน CLAUDE.md เป็นบริบทก่อน
แทนรายการตัวอย่างใน seed() ของ db.js ด้วยของจริง <จำนวน> รายการ ตามนี้:
1. <ชื่อ> ราคา <ราคา> — <คำอธิบายสั้น>
2. ...
เว้นช่อง image ว่างไว้ เดี๋ยวฉันจะอัปรูปเองในหน้าหลังบ้าน
```

## 4) เปลี่ยนคำเรียกให้ตรงกับธุรกิจ
```
อ่าน CLAUDE.md เป็นบริบทก่อน
ในข้อความที่ผู้ใช้เห็นบนหน้าเว็บ เปลี่ยนคำว่า "รายการ" เป็น "<คำที่ร้านฉันใช้ เช่น เมนู / คอร์ส / แพ็กเกจ>"
แก้เฉพาะข้อความที่แสดงผลใน public/*.html เท่านั้น
ห้ามเปลี่ยนชื่อตัวแปร ชื่อ field หรือ route ในโค้ด (item, /api/items ต้องคงเดิม)
```

## 5) ปรับหน้าแรกให้ตรงกับสิ่งที่อยากให้ลูกค้าทำ
```
อ่าน CLAUDE.md เป็นบริบทก่อน
ในหน้า public/index.html ฉันอยากให้ลูกค้าเห็น <อะไร> ก่อนเป็นอย่างแรก
และอยากให้ปุ่มหลักคือ "<ข้อความปุ่ม>" ซึ่งพาไปที่ <ที่ไหน>
ช่วยจัดลำดับส่วนต่าง ๆ ในหน้าแรกใหม่ให้ตรงกับนี้ แก้เฉพาะ index.html
```

## 6) เพิ่มช่องข้อมูลของรายการ
```
อ่าน CLAUDE.md เป็นบริบทก่อน
เพิ่มช่อง "<ชื่อช่อง เช่น ระยะเวลา>" ให้กับ item
ต้องแก้ให้ครบ 4 จุดตามตาราง "แก้อะไรบ่อย แก้ตรงไหน" ใน CLAUDE.md:
db.js (seed + createItem + updateItem), public/admin.html (ฟอร์มแก้ไข),
public/item.html (แสดงผล) และ public/index.html ถ้าต้องโชว์บนการ์ดด้วย
เสร็จแล้วบอกวิธีทดสอบว่าใช้ได้จริง
```

## 7) เพิ่มบล็อกความสามารถ
```
เปิดไฟล์ในโฟลเดอร์ บล็อก/ แล้วก๊อปพรอมต์ของบล็อกที่ต้องการมาวางที่นี่
ทำทีละบล็อก และทดสอบให้ผ่านก่อนค่อยทำอันถัดไป
```

## 8) เตรียมขึ้นออนไลน์
```
อ่าน CLAUDE.md เป็นบริบทก่อน
ช่วยไล่เช็กลิสต์ก่อน deploy ให้หน่อย:
- มีไฟล์ .env หลุดอยู่ในโฟลเดอร์ที่จะอัปไหม
- .gitignore กัน .env แล้วหรือยัง
- มีรหัสผ่านหรือคีย์ hardcode อยู่ในโค้ดตรงไหนบ้างไหม
- /health ยังตอบสั้น ๆ อยู่ไหม
แล้วบอกขั้นตอนอัปขึ้น GitHub → Render → ตั้ง Environment Variables ทีละขั้น
```

## 9) แก้บั๊ก
```
อ่าน CLAUDE.md เป็นบริบทก่อน
อาการ: <เล่าอาการที่เห็น เช่น กดปุ่มแล้วไม่มีอะไรเกิดขึ้น / รูปไม่ขึ้น / หน้าขาว>
ฉันทำอะไรก่อนหน้านั้น: <เล่า>
ช่วยหาสาเหตุแล้วแก้เฉพาะไฟล์ที่เกี่ยวข้อง
อธิบายสั้น ๆ ว่าแก้อะไรไป และต้องอัปไฟล์ไหนขึ้น GitHub บ้าง
```

## 10) หลังคลาส — วางแผนอัปเกรดต่อเอง
```
อ่าน CLAUDE.md เป็นบริบทก่อน แล้วดูเว็บที่ฉันมีตอนนี้
ช่วยเสนอ 5 อย่างที่ควรทำต่อ เรียงจากง่ายไปยาก
ข้อแรกต้องเป็นอย่างที่ฉันทำเองได้ใน 10 นาที
บอกด้วยว่าแต่ละข้อตรงกับบล็อกไหนในโฟลเดอร์ บล็อก/
```

---

### หลักคิดให้ AI ทำงานถูกและไม่กินโควตา
1. **บอกเป้าหมาย ไม่ใช่วิธี** — "อยากให้ลูกค้ากดจองได้จากหน้าแรก" ดีกว่า "เพิ่มปุ่มสีส้มขนาด 40px"
2. **ทีละงาน** — ทำเสร็จ ทดสอบ แล้วค่อยสั่งอันถัดไป
3. **ล็อกขอบเขต** — "แก้เฉพาะไฟล์ X" ทุกครั้ง
4. **ให้มันบอกวิธีทดสอบ** — จบทุกพรอมต์ด้วย "แล้วบอกวิธีทดสอบว่าใช้ได้จริง"
5. **พังเมื่อไหร่ ย้อนกลับ** — GitHub เก็บทุกเวอร์ชันไว้ ไม่ต้องกลัว
